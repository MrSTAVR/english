# English Fun — правила проекта для ИИ-ассистента

Веб-приложение для изучения английского ребёнком (10 лет, ученица «Маша»): Flask + SQLite, без фронтенд-сборки (чистый JS/CSS). Рядом ходит родитель (владелец проекта). Подробности о возможностях — в `README.md`, эксплуатация — в `deploy/OPERATIONS.md`.

Этот файл — единственный источник правил: его читает любой ассистент. Ниже сразу карта: что где лежит, включая бэклог и критиков.

## Как общаться
- Владелец говорит по-русски: отвечай по-русски, коротко и по делу. Тексты интерфейса — тоже по-русски, дружелюбно, для ребёнка.
- Окружение владельца: Windows + PyCharm, репозиторий `MrSTAVR/english` (ветка `main`).
- Валюта в учебных текстах — **рубли** (не фунты/доллары).

## Команды
- Запуск: `pip install -r requirements-dev.txt`, затем `python app.py` (http://localhost:5000). Пароль родителя по умолчанию `1234` (только для разработки).
- Тесты: `pytest` (конфиг в `pytest.ini`). **Перед каждым коммитом тесты должны быть зелёными.** Тесты идут с отключённым CSRF.
- Деплой на сервер (Debian, Caddy + systemd): автоматически из `main` раз в 5 минут; вручную — `bash /opt/english/app/deploy/update.sh`. Новые таблицы БД создаются сами при старте.
- Новые файлы не забывать добавлять в git (в PyCharm — «Add to VCS»).

Цвета — только из палитры макета (никаких градиентов в полосках и карточках). Меню: ученица — `.tabbar` в шапке, на телефоне внизу (`body.has-tabbar`, 6-я ячейка — Чик-чик); логопед — `body.sp-logoped`, ≥1024px слева, на телефоне внизу.
- **Урок** (`templates/lesson.html`, `static/lesson.css` + `static/lesson.js`, макет — артборды «Урок, шаг 1–4» телефон/компьютер): **тренировки в уроке нет** (владелец 29.10.2026: скучно, силы — на историю; данные `exercises`/`practice` в уроках остались, но не показываются; игры по словам урока — кнопка «Сыграй со словами урока» на странице результата). Шаги: урок со сценой — «Теория → Слова → История», без сцены — «Теория → Слова → Тест» (список шагов — `ls_steps` в шаблоне, `lesson.js` берёт их из шапки; шаг старого сохранения, которого больше нет, ведёт к тесту/истории). Шапка с шагами (на телефоне — крестик и полоска, верхнее меню скрыто, `body.lesson-focus`), теория карточками (английские фразы жирным озвучиваются по нажатию), «Новые слова» — одна большая карточка (перевод по нажатию, точки, «Дальше»), список всех слов справа или в шторке «Все слова»; данные — JSON `#wd-data` из `lesson.material`. Незаконченный урок сохраняется (`lesson_progress`, `POST /api/lesson/<id>/progress`: шаг и место на странице, слово, ответы теста, «Соедини пары», «Разложи по корзинам», собранные предложения, место в сцене — `window.LessonScene`, секунды; компоненты сообщают об изменениях событием `lesson:changed`) и восстанавливается при возврате (плашка «Продолжаем с того же места» + «Начать заново»); после сдачи теста строка стирается. Задания «напиши по-английски» (тест, сцена, повторение): под полем буквы-плитки и «Подсказка» (маска «f _ _ _») — `static/tiles.js`, плитки из фильтра `|tiles` (`template_filters.letter_tiles`, перемешаны одинаково при каждом открытии, ответ целиком в страницу не попадает); в тесте и сцене уроков курса до `TILES_UPTO` плитки открыты сразу, дальше — по кнопке; ответ с подсказкой/плитками (`q<i>_help`, ставится при нажатии плитки или кнопки) засчитывается, но слово уходит в повторение. Ответы сравниваются после `grading.norm_answer` (регистр, знаки препинания и внутри фразы, сокращения = полные формы: he's = he is, don't = do not — `CONTRACTIONS`; лишний артикль в начале ответа без артикля не ошибка — `drop_article`, «an egg» = «egg»; в браузере то же — `LetterTiles.norm`). Мелкие опечатки (`grading.near_answer`) засчитываются только в английских ответах: опечатка максимум в одном слове от 5 букв, первая буква та же, введено не другое слово курса (`grading.dictionary()` — все тексты уроков/историй/диалогов + `FUNCTION_WORDS`) и не другая форма (-s/-es/-ed/-ing, удвоенная буква); в результатах — «Засчитано! Только пишется так…», слово — в повторение; в браузере то же (`LetterTiles.near`, словарь урока — `#near-dict` из `grading.near_dict`). Варианты «выбери» в уроке перемешиваются стабильно (`|shuffle_options`, value — исходный индекс). Тест урока собирается в `practice.augment`: свои вопросы (лишние «напиши по-английски» сверх `MAX_WRITE`=2 на слова урока превращаются в «выбери» — `limit_writing`) + вопрос на слух + 1 повторение из прошлых уроков без фонетики (`review_extras`, `PHONICS_IDS`); итого не больше 10. Результат теста: при провале — «Не хватило N ответов» / «Этот урок пока трудный», главная кнопка «Исправь ошибки (N)» (`/lesson/<id>?step=test&fix=<attempt>`: верные ответы прошлой несданной попытки засчитаны — `routes/student.fix_correct`, вопросы скрыты `.fix-done`, на сдачу идёт `fix_from`; «Идеально» и бонус за 100% — только с первого раза), «Пройти весь тест заново» (`?step=test`), в разборе — только ошибки, у «выбери» — текст выбранного варианта. Повторная отправка теста: в течение минуты — на главную с сообщением, позже (страница из офлайн-кэша) — новая попытка; попытка другого урока — 400.
- **История «Поездка к Тому» вместо теста** (`data/story.py` — сюжет по островам и сцены `SCENES[id урока]`, `scenes.py` — данные для чата, `templates/_scene.html`, `static/scene.js`): у урока со сценой шаги «Теория → Слова → История» (владелец 29.10.2026: слова сначала карточками; в истории слова урока из `material` при первом появлении в реплике героя — ещё раз карточки под ней с картинкой, перевод по нажатию, в тексте слово подчёркнуто). История — чат: реплики героев (`say`, только английский, озвучиваются по очереди после кнопки «Начать историю»; кнопка «перевод», поэтому в реплике над вопросом не называем проверяемое слово; `{name}` — имя ученицы, в английском латиницей — `scenes.name_en`), слова рассказчика (`note`), ходы ученицы (`ask(q, ok=say(...), no=say(...) | {номер варианта: say(...)})` — choice (можно `pics=True` — варианты картинками) / type_in с `accept` / order, можно `audio`; `ok`/`no` — реакция героя на ответ, неверный ответ виден в чате зачёркнутым), выбор без правильного ответа (`pick(ключ, вопрос, [(en, ru, v, v_ru)…])` — дальше `{ключ}` в репликах; в тест не входит), «скажи вслух» (`speak(en, ru)` — по желанию, без оценки), в конце крючок `outro`. Правила хода для новых сцен (методист 29.10.2026): ход — реплика в разговоре, а не «выбери перевод»; без «напиши перевод по-русски»; письмо не больше 2 раз и по сюжету (записка, код, табличка); каждое ключевое слово — 3 раза (услышала → выбрала → применила); реакция `no` — максимум на 1 вариант; повторение прошлого — 1–2 хода `ask(..., review=True)` прямо в сюжете (метка «Вспомни!», случайного вопроса «Повторение» после сцены нет): ответ — фраза из материала уроков на 2–5 шагов раньше в `ORDER` (не из предыдущего; проверяет `validate_scenes`), хотя бы один неверный вариант — из слов текущего урока, фонетику/алфавит повторяем чтением записок и табличек; образец — сцена урока 10. Вопросы сцены и есть `lesson["test"]` (`practice.augment` без `limit_writing`/«на слух», `add_review_questions` сцены пропускает), поэтому сдача, «Исправь ошибки» (засчитанные ходы показываются ответом), монетки и повторение — как у теста. Ответ проверяется сразу (вторая попытка, после двух ошибок — верный ответ и сюжет идёт дальше); на сервер уходят первый ответ (`q<i>` / `q<i>_order`, балл) и второй (`q<i>_2` / `q<i>_order_2` — полбалла, слово всё равно в повторение); порог сцены — `config.PASS_MARK_SCENE`=60% (`curriculum.pass_mark`); место в сцене — `window.LessonScene` в `lesson_progress`. Проверка данных — `curriculum.validate_scenes` (5–`SCENE_MAX` ходов, известные герои, реакции, `{ключ}` только после `pick`), тесты — `tests/test_scenes.py`. Сделаны острова 1 («Первые шаги») и 2 («Я и моя семья», 61 «Проверь себя» — тоже сцена-финал «Видео Зои»); тексты новых сцен сначала проверяет `methodist`, потом читает владелец (страница-черновик из `data/story.py`).
- **Телефон:** вёрстка должна помещаться в 360px без горизонтальной прокрутки (узкие правки — в конце `theme.css`).
- **Кэш статики:** при правке JS/CSS поднимай `?v=N` у подключения в `templates/base.html` (или в шаблоне страницы), иначе у ребёнка останется старый файл. `sw.js` версионируется сам.
- **CSRF:** в формах — скрытое поле `csrf_token()`; в `fetch` — заголовок `X-CSRF-Token` из `<meta name="csrf-token">`. Токен вычисляется из зерна сессии (`csrf.new_seed()` — сразу после `session.clear()` при входе), не хранится: иначе параллельные запросы перетирали его в cookie и сохранения падали с «Форма устарела».
- В шаблонах HTML из данных урока выводится через `|safe` (теория), остальное экранируется.
- Серия дней (`garden.compute_streak_from_history`) считается по дням реальных занятий (`garden.study_days`: пройденный тест урока, `activity` — игра/история/диалог/урок, `daily_goal` со словами), открыть урок — не занятие. Каникулы родителя (таблица `vacations`) серию не прерывают; один пропущенный день тоже не рвёт («запасной день», не чаще раза в `FREEZE_EVERY`=7 дней). При разрыве сад «засыпает» (серый, дерево — жёлудь), украшения остаются. Монетки за тест — `garden.award_coins`: первая сдача `COIN_PASS` (+`COIN_PERFECT` за первые 100% не после «Исправь ошибки»), пересдача — `COIN_RETRY` только за новый лучший результат и раз в день на урок, провал от `EFFORT_MIN`% — `COIN_EFFORT` «за старание» раз в день. Крыша замка — за `castle.ROOF_DAYS`=10 дней занятий всего; награды `days_10/20/40` (метрика `study_days`). Любые правки в `garden.py` проверяй тестами `tests/test_vacation.py`, `tests/test_garden.py`, `tests/test_coins.py`.
- Офлайн: `static/sw.js` кэширует посещённые страницы уроков/игр (`OFFLINE_OK`), при выходе из аккаунта кэш страниц стирается. Новая страница ученика, которая должна работать офлайн, добавляется в regex `OFFLINE_OK`.
- **Кэш service worker и подмена файлов:** статика кэшируется по полному адресу, включая `?v=N` (`cache.match(req)`, без `ignoreSearch` — 30.10.2026: из-за него после выкатки новые js/css/модели не доезжали до ребёнка). Поэтому при правке js/css поднимаем `?v=N`, а **подменённая 3D-модель фермы получает новое имя файла** (`chicken.glb` → `hen.glb`, `tree3.glb` → `fruittree.glb`) и общий `MODELS` в `static/farm.js` — старый адрес из кэша телефона иначе перебьёт новую модель.

## Как делаем изменения
1. Небольшой шаг → тесты (добавляем новые в `tests/`) → проверка в браузере для UI (Playwright + Chromium, если нужно).
2. Публикация делается целиком самостоятельно (как «Commit and Push» в PyCharm): тесты зелёные → коммит → push в рабочую ветку → PR через REST API (`gh api repos/MrSTAVR/english/pulls -X POST …`; GraphQL в облачных сессиях закрыт, `gh pr …` не работает) → дождаться зелёного CI (GitHub Actions `tests`: Python 3.11 как на сервере, `pytest`; статус — `gh api repos/MrSTAVR/english/commits/<sha>/check-runs`) → merge (`gh api repos/MrSTAVR/english/pulls/<N>/merge -X PUT`). Если тесты или CI красные или merge не прошёл — не сливать, сообщить владельцу.
3. Выкатка: сервер сам подтягивает `main` раз в 5 минут (`deploy/autoupdate.sh` + таймер `english-autoupdate.timer`, включается `deploy/setup-autoupdate.sh`), при поломке откатывается; кабинет администратора управляет им через «записки» в `/opt/english/data/control` (`updates.py`, блок «Обновления сайта»: журнал, «Обновить сейчас», вкл/выкл). Если сервер под рукой недоступен — выкатку проверить нельзя; если владелец сообщает о проблеме, смотреть `journalctl -u english-autoupdate`. Новые таблицы БД — только аддитивно (`CREATE TABLE IF NOT EXISTS`/`ALTER TABLE ADD`), чтобы откат кода не ломал базу.
4. Критики проекта — брифы в `agents/` (`methodist` — английский и методика, `kid-ux` — взгляд ребёнка и телефон, `design-critic` — макет, `game-balance` — монетки и награды, `code-critic` — правила этого файла, `qa` — тесты и поведение; порядок прогона и формат сводки — `agents/README.md`); общий прогон — после крупного блока изменений (владелец 30.10.2026: прогонять **по согласованию**, а не молча — сначала спросить, каких критиков и по какому блоку; брифы — обычный markdown, поэтому их можно отдать субагенту любого ассистента без правок).
