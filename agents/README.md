# Критики проекта

Независимая проверка после крупного блока изменений. Критик **читает** код, данные и скриншоты, запускает тесты и пишет отчёт; **править код ему нельзя** — что брать в работу, решает владелец.

Файлы рядом — готовые брифы. Это обычный markdown: его можно отдать субагенту любого ассистента как инструкцию, без правок. Формат отчёта у каждого критика свой и описан внутри.

## Кто есть

| Бриф | Что смотрит | Когда звать |
|---|---|---|
| `methodist.md` | английский, методика, нагрузка, прогрессия курса | уроки, истории, диалоги, праздники, любые английские тексты в интерфейсе |
| `kid-ux.md` | понятность и удобство глазами 10-летней, телефон 360px | страницы ученицы: `templates/`, `static/*.js|css`, `routes/student.py` |
| `design-critic.md` | дизайн-система: палитра, переменные, иконки, тёмные темы, `?v=N` | `templates/`, CSS, SVG-рисунки |
| `game-balance.md` | экономика: монетки, капли, награды, серии, мотивация | правки в наградах и прогрессе (`garden.py`, `farm.py`, `achievements.py`, `weekly.py`…) |
| `code-critic.md` | правила `AGENTS.md`: ошибки, CSRF, миграции, кэш, тесты, линтер | любой Python/JS/шаблон |
| `qa.md` | поведение: тесты, краевые случаи, гонки, миграции, хрупкость тестов | новая логика, правки БД, релизы |

Логопедическая часть (`speech*`, `templates/speech/`) — только `design-critic` и `code-critic`; остальные её не касаются.

## Как запускать

1. Определить объём: диапазон коммитов (`git diff main...HEAD --stat`), файлы, уроки или страницы. Если непонятно — спросить владельца.
2. Выбрать критиков по таблице выше (или взять тех, кого назвал владелец).
3. Запустить **параллельно**, каждому в промпте: объём (файлы/коммиты) + 2–3 предложения контекста «что за фича и зачем» + просьба вернуть отчёт в своём формате. Бриф читается как есть.
4. Свести отчёты в один: убрать дубли, сомнительные находки проверить по коду, явно ложные отбросить.
5. Показать владельцу сводку и **спросить, что брать в работу**. Самому не чинить.

Запуск — по согласованию с владельцем, а не молча (правило в `AGENTS.md`).

## Формат сводки владельцу

```
## Итоги критики
Кто смотрел: ...  Общее впечатление: 2–3 предложения.

### Исправить обязательно
1. [критик] `файл:строка` — суть → предложение

### Стоит сделать
...
### Можно потом / в бэклог
...
### Расхождения мнений
(если критики противоречат друг другу — кратко, с рекомендацией)
```
