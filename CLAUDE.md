# English Fun — заметки для Claude Code

Веб-приложение для изучения английского ребёнком (10 лет, ученица «Маша»): Flask + SQLite, без фронтенд-сборки (чистый JS/CSS). Рядом ходит родитель (владелец проекта). Подробности о возможностях — в `README.md`, эксплуатация — в `deploy/OPERATIONS.md`.

## Как общаться
- Владелец говорит по-русски: отвечай по-русски, коротко и по делу. Тексты интерфейса — тоже по-русски, дружелюбно, для ребёнка.
- Окружение владельца: Windows + PyCharm, репозиторий `MrSTAVR/english` (ветка `main`).
- Валюта в учебных текстах — **рубли** (не фунты/доллары).

## Команды
- Запуск: `pip install -r requirements-dev.txt`, затем `python app.py` (http://localhost:5000). Пароль родителя по умолчанию `1234` (только для разработки).
- Тесты: `pytest` (конфиг в `pytest.ini`). **Перед каждым коммитом тесты должны быть зелёными.** Тесты идут с отключённым CSRF.
- Деплой на сервер (Debian, Caddy + systemd): автоматически из `main` раз в 5 минут; вручную — `bash /opt/english/app/deploy/update.sh`. Новые таблицы БД создаются сами при старте.
- Новые файлы не забывать добавлять в git (в PyCharm — «Add to VCS»).

## Структура
- `app.py` — приложение; `routes/*.py` — blueprint-ы (`student`, `parent`, `garden`, `games`, `stories`, `writing`, `review`, `wardrobe`, `house`, `season`, `speak`, `pwa`, `auth`, `system`); регистрируются в `routes/__init__.py`.
- `database.py` — схема `SCHEMA` и миграции в `init_db()` (`PRAGMA table_info` + `ALTER TABLE`). Новая таблица = `CREATE TABLE IF NOT EXISTS` в схеме. При удалении ученика чистим его строки во всех таблицах (`routes/parent.py: delete_student`).
- Контент: `data/lessons.py`, `new_lessons.py`, `more_lessons.py`, `later_lessons.py` (52–56: was/were, -ed/did, сравнения, «как часто», путешествия), `extra_lessons.py` → `curriculum.py` собирает `LESSONS` / `ALL_LESSONS` / `LESSONS_BY_ID`. Порядок прохождения задаёт `data/course.py` (`ORDER`), он не равен id урока. Диалоги — `data/dialogs.py`, истории — `data/stories.py`, праздники — `data/halloween.py`, `newyear.py` (+ `ADVENT` — 31 окошко), `march8.py`, `easter.py`, `birthday.py` (слова, викторина, тексты страницы), эмодзи — `data/emoji.py`.
- Логика: `stats.py` (`compute_stats`), `achievements.py` (ачивки через `_m(...)`), `garden.py` (серия дней, монеты), `review.py` (повторение, система Лейтнера; ошибки теста урока → `send_mistakes` кладёт слова в коробку 0), `goals.py` (цель дня; своя цель родителя — таблица `goal_settings`), `report.py` (недельный отчёт `/parent?week=N`; блок «Прогресс за 12 недель»: `activity_heatmap`, `score_trend`, `hard_words` + «в повторение»), `wardrobe.py`, `house.py`, `stickers.py`, `weekly.py` (недельный челлендж и босс), `seasons.py` (праздничные сезоны), `activity.py` (журнал занятий по дням), карта курса — `/student/map` (`routes/student.py: course_map`, острова по 9 уроков), `writing.py`, `practice.py`, `mascot.py`.
- Фронтенд: `templates/` (Jinja), `static/` (`style.css`, `theme.css` — тема перекрывает style.css, `games.js`, `stories.js`, `writing.js`, `chick.js` — рисунок цыплёнка и наряды, `house.js`, `mascot.js`, `tts.js`, `sw.js`, `pwa.js`…).

## Важные правила и ловушки
- **Кэш статики:** при правке JS/CSS поднимай `?v=N` у подключения в `templates/base.html` (или в шаблоне страницы), иначе у ребёнка останется старый файл. `sw.js` версионируется сам.
- **CSRF:** в формах — скрытое поле `csrf_token()`; в `fetch` — заголовок `X-CSRF-Token` из `<meta name="csrf-token">`.
- В шаблонах HTML из данных урока выводится через `|safe` (теория), остальное экранируется.
- Серия дней: каникулы родителя (таблица `vacations`) серию не прерывают — любые правки в `garden.py` проверяй тестами `tests/test_vacation.py`, `tests/test_garden.py`.
- Офлайн: `static/sw.js` кэширует посещённые страницы уроков/игр (`OFFLINE_OK`), при выходе из аккаунта кэш страниц стирается. Новая страница ученика, которая должна работать офлайн, добавляется в regex `OFFLINE_OK`.
- Праздники: `seasons.SEASONS` (даты `start`/`end` могут переходить через Новый год; у Пасхи `window` — православная Пасха считается `orthodox_easter`), свои даты родителя можно сделать «каждый год» (`season_<key>_yearly`). День рождения — личный праздник: `students.birthday` (поле в кабинете администратора), неделя после даты, страница `/student/birthday` (общий `season.html`), подарок `BIRTHDAY_GIFT` монет раз в год (`birthday_gifts`). `seasons.active_season()` учитывает настройку родителя (авто / включён / выключен + свои даты, таблица `app_settings`). Новый праздник = запись в `SEASONS` + `data/<key>.py` с теми же полями, что у `halloween.py`; страница `/student/<key>` и `/api/<key>` общие (`templates/season.html`, `static/season.js`). Адвент-календарь (`/student/advent`, таблица `advent`) — весь декабрь, выключается вместе с Новым годом; монетка только за окошко, открытое в свой день. Снегопад — `snow` в `app.py` (context processor). Сезонные наряды покупаются только в сезон; купленное остаётся навсегда.
- Награды босса (`source: "boss"`) в магазине не продаются, выдаются через `wardrobe.grant`.
- Игры сохраняют результат через `/api/game` (звёзды 0–3, таблица `game_scores`); «игры на 3 звезды» для ачивок считаются только по 5 играм (без `build`/`dictation`).
- Кабинет администратора (бывший «кабинет родителя»): вход — страница `/admin` (на главной только кнопка ⚙ в левом нижнем углу), сам кабинет — `/parent`. Внутри кода роль по-прежнему называется `parent` (сессия, `require_role`, тесты).
- **Логопедическая часть** (отдельно от English Fun, для жены владельца — логопеда на дому): `speech.py` + `routes/speech.py` (blueprint `speech`), шаблоны `templates/speech/`, таблицы с префиксом `sp_`. Роли в сессии: `logoped` (`logoped_id`), `family` (`client_id`, «Кабинет родителя» — аккаунт ребёнка, им пользуется родитель). Вход: `/logoped`, `/family`. Аккаунты логопедов создаёт администратор (блок «Логопеды»), учеников — логопед. На страницах `speech` (`speech_area` в шаблонах) нет Чик-чика и бренда English Fun. Логопед видит только своих учеников (`speech.client_of`). Диагноз и программа — только для логопеда, никогда не показывать семье.
- Версия: `version.py` (из git, `v1.<число коммитов>`), показывается в подвале и на `/version`.
- В тестах `database.DB_PATH` (не `config`); хелперы в `tests/helpers.py`, фикстуры `parent`, `make_student`, `anon` в `tests/conftest.py`.

## Как делаем изменения
1. Небольшой шаг → тесты (добавляем новые в `tests/`) → проверка в браузере для UI (Playwright + Chromium, если нужно).
2. Публикация делается целиком самостоятельно (как «Commit and Push» в PyCharm): тесты зелёные → коммит → push в рабочую ветку → PR через REST API (`gh api repos/MrSTAVR/english/pulls -X POST …`; GraphQL в облачных сессиях закрыт, `gh pr …` не работает) → дождаться зелёного CI (GitHub Actions `tests`: Python 3.11 как на сервере, `pytest`; статус — `gh api repos/MrSTAVR/english/commits/<sha>/check-runs`) → merge (`gh api repos/MrSTAVR/english/pulls/<N>/merge -X PUT`). Если тесты или CI красные или merge не прошёл — не сливать, сообщить владельцу.
3. Выкатка: сервер сам подтягивает `main` раз в 5 минут (`deploy/autoupdate.sh` + таймер `english-autoupdate.timer`, включается `deploy/setup-autoupdate.sh`), при поломке откатывается; кабинет администратора управляет им через «записки» в `/opt/english/data/control` (`updates.py`, блок «Обновления сайта»: журнал, «Обновить сейчас», вкл/выкл). Сервер Claude недоступен — проверить выкатку нельзя; если владелец сообщает о проблеме, смотреть `journalctl -u english-autoupdate`. Новые таблицы БД — только аддитивно (`CREATE TABLE IF NOT EXISTS`/`ALTER TABLE ADD`), чтобы откат кода не ломал базу.
4. Крупные фичи согласуем списком заранее; отложенное — в бэклоги ниже (English Fun и кабинет логопеда — отдельно).
