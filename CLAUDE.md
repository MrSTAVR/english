# English Fun — заметки для Claude Code

Веб-приложение для изучения английского ребёнком (10 лет, ученица «Маша»): Flask + SQLite, без фронтенд-сборки (чистый JS/CSS). Рядом ходит родитель (владелец проекта). Подробности о возможностях — в `README.md`, эксплуатация — в `deploy/OPERATIONS.md`.

## Как общаться
- Владелец говорит по-русски: отвечай по-русски, коротко и по делу. Тексты интерфейса — тоже по-русски, дружелюбно, для ребёнка.
- Окружение владельца: Windows + PyCharm, репозиторий `MrSTAVR/english` (ветка `main`).
- Валюта в учебных текстах — **рубли** (не фунты/доллары).

## Команды
- Запуск: `pip install -r requirements-dev.txt`, затем `python app.py` (http://localhost:5000). Пароль родителя по умолчанию `1234` (только для разработки).
- Тесты: `pytest` (конфиг в `pytest.ini`). **Перед каждым коммитом тесты должны быть зелёными.** Тесты идут с отключённым CSRF.
- Деплой на сервер (Debian, Caddy + systemd): автоматически из `main` раз в 5 минут; вручную — `bash /opt/english/app/deploy/update.sh`. Новые таблицы БД создаются сами при старте.
- Новые файлы не забывать добавлять в git (в PyCharm — «Add to VCS»).

## Структура
- `app.py` — приложение; `routes/*.py` — blueprint-ы (`student`, `parent`, `garden`, `games`, `stories`, `writing`, `review`, `wardrobe`, `house`, `season`, `speak`, `pwa`, `auth`, `system`, `friends`); регистрируются в `routes/__init__.py`.
- `database.py` — схема `SCHEMA` и миграции в `init_db()` (`PRAGMA table_info` + `ALTER TABLE`). Новая таблица = `CREATE TABLE IF NOT EXISTS` в схеме. При удалении ученика чистим его строки во всех таблицах (`routes/parent.py: delete_student`).
- Контент: `data/lessons.py`, `new_lessons.py`, `more_lessons.py`, `later_lessons.py` (52–60: was/were, -ed/did, сравнения, «как часто», путешествия, неправильные глаголы, will, going to, в гостях), `extra_lessons.py` (+ в конец — `castle_lessons.py`: 6 уроков замка Чик-чика, id 20001–20006, поле `castle` — комната; примеры про зверят-соседей Benny, Olly, Mia, Felix, Max, Bella) → `curriculum.py` собирает `LESSONS` / `ALL_LESSONS` / `LESSONS_BY_ID`. Порядок прохождения задаёт `data/course.py` (`ORDER`), он не равен id урока. Диалоги — `data/dialogs.py`, истории — `data/stories.py`, праздники — `data/halloween.py`, `newyear.py` (+ `ADVENT` — 31 окошко), `march8.py`, `easter.py`, `birthday.py` (слова, викторина, тексты страницы), эмодзи — `data/emoji.py`.
- Логика: `stats.py` (`compute_stats`), `achievements.py` (ачивки через `_m(...)`), `garden.py` (серия дней, монеты), `review.py` (повторение, система Лейтнера; ошибки теста урока → `send_mistakes` кладёт слова в коробку 0), `goals.py` (цель дня; своя цель родителя — таблица `goal_settings`), `report.py` (недельный отчёт `/parent/progress?week=N`; блок «Прогресс за 12 недель»: `activity_heatmap`, `score_trend`, `hard_words` + «в повторение»), `wardrobe.py`, `castle.py` (замок, см. ниже), `house.py` (старый домик — только цены вещей для возврата монеток), `stickers.py`, `weekly.py` (недельный челлендж и босс), `seasons.py` (праздничные сезоны), `activity.py` (журнал занятий по дням), карта курса — `/student/map` (`routes/student.py: course_map`, острова по 9 уроков), `writing.py`, `practice.py`, `mascot.py`, `friends.py` («Друзья», см. ниже).
- Фронтенд: `templates/` (Jinja), `static/` (`style.css`, `theme.css` — тема перекрывает style.css, `games.js`, `stories.js`, `writing.js`, `chick.js` — рисунок цыплёнка и наряды, `house.js`, `mascot.js`, `tts.js`, `sw.js`, `pwa.js`…).

## Важные правила и ловушки
- **Дизайн:** ориентир — макет «English Fun — дизайн-ориентир» в Claude Design (https://claude.ai/artifact/ExEnrW7GntAQH3XFo2r4RD). English Fun: кремовый фон `#FFF7E8`, синий акцент `#2563C9`, жёлтый `#FFC83D` (Чик-чик и главная кнопка), белые карточки с рамкой 2px `#F0E3C8` и тенью снизу, Nunito. Логопед и семья (`body.area-speech`): бирюза `#1F6F66`, Manrope, тонкие рамки без теней, без Чик-чика. Цвета — только через переменные (`--primary`, `--tint`, `--line`…), их задаёт `static/design.css` (подключён последним, там же тёмные темы обеих частей). Шрифты локальные (`tools/fetch_fonts.py`). У Чик-чика один клюв. **Значки:** цветных эмодзи в интерфейсе нет — только картинки к словам в уроках/играх, рисунки сада/домика/наклеек и босс; иконки — контурные из спрайта в `base.html` (`<svg class="ico"><use href="#o-sound"/></svg>`, `#o-*`, `#i-*` кроме цветных `#i-coin`/`#i-chick`); тексты из данных (названия уроков, баннеры, сообщения) выводим через фильтр `|noemoji`, реплики Чик-чика чистит `mascot.js`. Цвета — только из палитры макета (никаких градиентов в полосках и карточках). Меню: ученица — `.tabbar` в шапке, на телефоне внизу (`body.has-tabbar`, 6-я ячейка — Чик-чик); логопед — `body.sp-logoped`, ≥1024px слева, на телефоне внизу.
- **Урок** (`templates/lesson.html`, `static/lesson.css` + `static/lesson.js`, макет — артборды «Урок, шаг 1–4» телефон/компьютер): шапка с шагами (на телефоне — крестик и полоска из 4 частей, верхнее меню скрыто, `body.lesson-focus`), теория карточками (английские фразы жирным озвучиваются по нажатию), «Новые слова» — одна большая карточка (перевод по нажатию, точки, «Дальше»), список всех слов справа или в шторке «Все слова»; данные — JSON `#wd-data` из `lesson.material`. Незаконченный урок сохраняется (`lesson_progress`, `POST /api/lesson/<id>/progress`: шаг и место на странице, слово, выбранные ответы, введённые слова, проверенные задания, «Соедини пары», «Разложи по корзинам», собранные слова/предложения, реплика в каждом диалоге — `window.LessonDialogs.get/set` в `dialogs.js`, сказанные слова «Скажи вслух» — `#speak-block._speak.get/set` в `speak.js`, секунды; компоненты сообщают об изменениях событием `lesson:changed`) и восстанавливается при возврате (плашка «Продолжаем с того же места» + «Начать заново»); после сдачи теста строка стирается.
- **Телефон:** вёрстка должна помещаться в 360px без горизонтальной прокрутки (узкие правки — в конце `theme.css`).
- **Кэш статики:** при правке JS/CSS поднимай `?v=N` у подключения в `templates/base.html` (или в шаблоне страницы), иначе у ребёнка останется старый файл. `sw.js` версионируется сам.
- **CSRF:** в формах — скрытое поле `csrf_token()`; в `fetch` — заголовок `X-CSRF-Token` из `<meta name="csrf-token">`. Токен вычисляется из зерна сессии (`csrf.new_seed()` — сразу после `session.clear()` при входе), не хранится: иначе параллельные запросы перетирали его в cookie и сохранения падали с «Форма устарела».
- В шаблонах HTML из данных урока выводится через `|safe` (теория), остальное экранируется.
- Серия дней: каникулы родителя (таблица `vacations`) серию не прерывают — любые правки в `garden.py` проверяй тестами `tests/test_vacation.py`, `tests/test_garden.py`.
- Офлайн: `static/sw.js` кэширует посещённые страницы уроков/игр (`OFFLINE_OK`), при выходе из аккаунта кэш страниц стирается. Новая страница ученика, которая должна работать офлайн, добавляется в regex `OFFLINE_OK`.
- Праздники: `seasons.SEASONS` (даты `start`/`end` могут переходить через Новый год; у Пасхи `window` — православная Пасха считается `orthodox_easter`), свои даты родителя можно сделать «каждый год» (`season_<key>_yearly`). День рождения — личный праздник: `students.birthday` (поле в кабинете администратора), неделя после даты, страница `/student/birthday` (общий `season.html`), подарок `BIRTHDAY_GIFT` монет раз в год (`birthday_gifts`). `seasons.active_season()` учитывает настройку родителя (авто / включён / выключен + свои даты, таблица `app_settings`). Новый праздник = запись в `SEASONS` + `data/<key>.py` с теми же полями, что у `halloween.py`; страница `/student/<key>` и `/api/<key>` общие (`templates/season.html`, `static/season.js`). Адвент-календарь (`/student/advent`, таблица `advent`) — весь декабрь, выключается вместе с Новым годом; монетка только за окошко, открытое в свой день. Снегопад — `snow` в `app.py` (context processor). Сезонные наряды покупаются только в сезон; купленное остаётся навсегда.
- **«Друзья» (соревнования):** `friends.py` + `routes/friends.py`, страница `/student/friends` (плитка в «Мой мир», бейдж — `news_count`, баннер вызова на главной). Участвуют ученики с `students.competitions=1` (переключатель «Соревнования» в карточке ученика у администратора); другим видны только имя и аватарка. Рекорды — `game_records` (что считаем и в какую сторону — `friends.RECORDS`, `/api/game` принимает `score`); дуэли — `duels` (одинаковые слова из общих выученных, одна попытка у каждого, вызвавший играет первым, ждём `DUEL_DAYS`, монетки за первые `DUEL_COINS_PER_DAY` дуэли в день; игра открывается `?duel=<id>`); лента — `feed` (`friends.post`: первый сданный урок, новые награды из `update_achievements`, рекорд среди друзей, итог дуэли) и готовые реакции `feed_reactions` (без свободного текста); «в гостях» — `/student/friends/<id>/garden|house` и «нравится» (`likes`). Тексты ленты — без имён в косвенных падежах и без глаголов с родом («Урок пройден: …»).
- **Замок Чик-чика** (вместо домика; `/student/house` → редирект): `castle.py` + `routes/castle.py`, рисунки — `castle_art.py` (SVG комнат, зверят-соседей, кирпичика, ворот), шаблоны `castle.html`, `castle_room.html`, макрос `_castle.html` (импорт `with context`), `static/castle.css|js`. Таблицы `castle` (переезд: при первом входе `ensure` возвращает монетки за вещи домика и стирает их), `castle_rooms` (уровень 1–3), `castle_bricks` (журнал кирпичиков, UNIQUE(reason, ref) — начисление один раз). Кирпичики только за учёбу: первый сданный урок (`on_lesson_passed` в `submit_test`), урок замка (уроки 20001–20006, `data/castle_lessons.py`), цель дня (`goals.add`). Комнаты (`ROOMS`, `FLOORS`) открываются уроком/историей/серией, стоят кирпичики + монетки (`COST`), уровень даёт больше слов-предметов (`room_words`). Жители — зверята (Benny, Olly, Mia, Felix, Max, Bella). «В гостях» у друга показывает его замок (`what='house'` оставлен ради старых «нравится»). Предметы-слова на рисунке комнаты: `castle_art.POS` (координаты в viewBox 300×180; размер 0 — предмет уже нарисован, иначе рисуется картинка слова), `castle.scene(key, level)` → рисунок + метки; у каждого слова комнаты должно быть место (тест `test_every_room_word_has_place`). Игра «Find the…!» на странице комнаты (`castle.js`), `POST /api/castle/<room>/find` — кирпичик раз в день за комнату. Дальше: поручения соседей и доход комнат.
- Награды босса (`source: "boss"`) в магазине не продаются, выдаются через `wardrobe.grant`.
- Игры сохраняют результат через `/api/game` (звёзды 0–3, таблица `game_scores`); «игры на 3 звезды» для ачивок считаются только по 5 играм (без `build`/`dictation`).
- Кабинет администратора (бывший «кабинет родителя»): вход — страница `/admin` (на главной только кнопка ⚙ в левом нижнем углу). Разделы-вкладки (`templates/admin/_layout.html`, `routes/parent.py`): `/parent` обзор, `/parent/students` и `/parent/students/<id>` (аватарка — `students.emoji`, видна рядом с именем на главной ученика; цель дня, день рождения, каникулы, сад, зачёт уроков, пароль/удаление), `/parent/progress?week=N`, `/parent/mistakes`, `/parent/holidays`, `/parent/logopeds`, `/parent/updates`. Действия с учеником возвращают на его страницу. Внутри кода роль по-прежнему называется `parent` (сессия, `require_role`, тесты).
- **Логопедическая часть** (отдельно от English Fun, для жены владельца — логопеда на дому): `speech.py` + `routes/speech.py` (blueprint `speech`), шаблоны `templates/speech/`, таблицы с префиксом `sp_`. Роли в сессии: `logoped` (`logoped_id`), `family` (`client_id`, «Кабинет родителя» — аккаунт ребёнка, им пользуется родитель). Вход: `/logoped`, `/family`. Аккаунты логопедов создаёт администратор (блок «Логопеды»), учеников — логопед. На страницах `speech` (`speech_area` в шаблонах) нет Чик-чика и бренда English Fun. Логопед видит только своих учеников (`speech.client_of`). Диагноз и программа — только для логопеда, никогда не показывать семье.
- Ошибки: никаких `except Exception` — ловим конкретные исключения, неожиданное пишем в журнал (`logging`, на сервере — `journalctl -u english`); линтер `python -m pyflakes *.py routes data` (код приложения, без тестов) должен быть чистым.
- **Telegram-бот администратора** (`tg.py`, вкладка `/parent/telegram`): токен и чат хранятся в `app_settings` (`tg_*`), вводятся в кабинете; Bot API через `urllib` без зависимостей. Ночной `backup_db.py` (cron 03:17) отправляет копию в бот с инструкцией по восстановлению в подписи (`tg.restore_help`, адрес сервера — `tg_server`, запоминается из кабинета), `update.sh` вызывает его с `--no-telegram`. В тестах Telegram подменяется (`tests/test_telegram.py`, `FakeTelegram`). Дальше в бота можно добавлять уведомления администратору.
- Версия: `version.py` (из git, `v1.<число коммитов>`), показывается в подвале и на `/version`.
- В тестах `database.DB_PATH` (не `config`); хелперы в `tests/helpers.py`, фикстуры `parent`, `make_student`, `anon` в `tests/conftest.py`.

## Как делаем изменения
1. Небольшой шаг → тесты (добавляем новые в `tests/`) → проверка в браузере для UI (Playwright + Chromium, если нужно).
2. Публикация делается целиком самостоятельно (как «Commit and Push» в PyCharm): тесты зелёные → коммит → push в рабочую ветку → PR через REST API (`gh api repos/MrSTAVR/english/pulls -X POST …`; GraphQL в облачных сессиях закрыт, `gh pr …` не работает) → дождаться зелёного CI (GitHub Actions `tests`: Python 3.11 как на сервере, `pytest`; статус — `gh api repos/MrSTAVR/english/commits/<sha>/check-runs`) → merge (`gh api repos/MrSTAVR/english/pulls/<N>/merge -X PUT`). Если тесты или CI красные или merge не прошёл — не сливать, сообщить владельцу.
3. Выкатка: сервер сам подтягивает `main` раз в 5 минут (`deploy/autoupdate.sh` + таймер `english-autoupdate.timer`, включается `deploy/setup-autoupdate.sh`), при поломке откатывается; кабинет администратора управляет им через «записки» в `/opt/english/data/control` (`updates.py`, блок «Обновления сайта»: журнал, «Обновить сейчас», вкл/выкл). Сервер Claude недоступен — проверить выкатку нельзя; если владелец сообщает о проблеме, смотреть `journalctl -u english-autoupdate`. Новые таблицы БД — только аддитивно (`CREATE TABLE IF NOT EXISTS`/`ALTER TABLE ADD`), чтобы откат кода не ломал базу.
4. Крупные фичи согласуем списком заранее; отложенное — в бэклоги ниже (English Fun и кабинет логопеда — отдельно).
